# 易衍·Evomorph — 架构与设计文档

## 设计哲学

易衍·Evomorph 的设计融合了三个核心思想：

1. **《易经》卦象体系**：六十四卦对应六十四条原子指令，操作码直接编码为爻位二进制
2. **生物进化机制**：代码作为"基因座"，通过遗传算法（变异、交叉、选择）自动优化
3. **自然语言编程**：象辞（Xiangci）将自然语言意图映射为卦象指令序列

## 核心模块

### 1. 编译器 (evomorph/compiler/)

#### 词法分析器 (lexer.py)

将 `.evo` 源码分解为 Token 流。支持：

- 卦象符号（Unicode ䷀~䷿）
- 助记符（CREA, RECV, SYNC 等 64 个）
- 拼音名（QIAN, KUN, JIJI 等）
- 寄存器（R0~R15, R_FP, R_SP, R_LR, R_A0）
- 立即数（十进制、十六进制 0x、二进制 0b）
- 修饰符（.ASYNC, .ATOMIC, .PRIV, .WEAK, .STRONG, .VOLATILE）
- 关键字（@evolang, @locus, @meta_locus, @xiangci, 卦序）
- 适应度关键词（min_latency, max_throughput, min_energy, min_size）
- 注释（// 单行）

#### 语法分析器 (parser.py)

将 Token 流构建为 AST（抽象语法树）。AST 节点类型：

- `ProgramNode` — 程序根节点
- `LocusNode` — 基因座
- `MetaLocusNode` — 元基因座
- `XiangciNode` — 象辞块
- `InstructionNode` — 指令
- `FitnessExpr` / `FitnessTerm` — 适应度表达式
- `OperandNode` — 操作数

#### 代码生成器 (codegen.py)

将 AST 转换为输出格式：

- **dict** — Python 字典（供内部使用）
- **json** — JSON 字符串（供外部工具使用）
- **evb** — EVB 二进制字节码

字节码编码格式：
```
byte1 = (opcode[5:0] << 2) | (modifier[5:4])
byte2 = modifier[3:0]
[operand bytes...]
```

寄存器编码为 1 字节，立即数编码为 4 字节大端序。

### 2. 虚拟机 (evomorph/vm/)

#### IChingVM

栈式虚拟机，支持：

- 16 个通用寄存器（R0~R15，含 4 个特殊寄存器）
- 64KB 栈空间
- 1MB 堆空间
- 256 个未来值（FUTU 异步占位符）
- 互斥锁表
- 屏障同步表
- IO 处理器注册
- 事件监听器
- 执行追踪日志
- 能耗计算

VM 状态机：
```
INIT → RUNNING → HALTED
                → PAUSED → RUNNING
                → ERROR
                → TRAPPED
```

### 3. 进化引擎 (evomorph/evolution/)

#### EvolutionEngine

基于遗传算法的代码优化引擎：

- **变异**：翻转爻位（bit flip），修改修饰符，改变操作数
- **交叉**：单点交叉、两点交叉、均匀交叉
- **选择**：轮盘赌、锦标赛、排名选择
- **精英保留**：每代保留最优个体
- **收敛检测**：基于适应度方差的自动停止
- **交叉池**：不同基因座间的基因交换

#### GeneInstruction

基因指令，对应一条卦象指令：
- `opcode` — 操作码（6 bit，对应六爻）
- `modifier` — 修饰符（6 bit）
- `operands` — 操作数列表

变异操作 `flip_yao(position)` 翻转指定爻位，对应操作码的 bit 位翻转。

### 4. 平台模拟 (evomorph/simulator/)

#### PlatformSimNiche

模拟不同平台的性能特征，为进化引擎提供适应度评估：

- 系统调用开销
- 内存延迟
- 线程创建成本
- 锁开销
- 同步开销
- IO 开销
- 每周期能耗
- SIMD 可用性
- 最大线程数

### 5. 象辞 SDK (evomorph/sdk/)

#### XiangciSDK

将自然语言意图翻译为卦象指令：

- 关键词匹配模板（并行、IO、计算等）
- 自定义处理器注册
- 模型能力管理
- 翻译历史记录
- 记忆库
- 导出为 .evo 源码

### 6. 自举系统 (evomorph/bootstrap/)

三阶段自举策略：

- **Phase 1**：Python 实现核心基础设施
- **Phase 2**：用 .evo 格式编写编译器组件（词法分析、语法分析、代码生成）
- **Phase 3**：完全自寄主，易衍编译自身

自举编译器组件：
- `evoc/lexer.evo` — 词法分析器基因座
- `evoc/parser.evo` — 语法分析器基因座
- `evoc/codegen.evo` — 代码生成器基因座
- `evoc/evolved/` — 进化后的编译器子基因座
- `meta/evolution.evo` — 编译器进化策略

### 7. 原生模块 (evomorph/native/)

- **Linker** — 多文件 EVB 链接器
- **Loader** — EVB 字节码加载器
- **Image** — EVOI 可执行映像生成
- **Shell** — EvoShell 命令行运行环境
- **REPL** — EvoREPL 交互式编程环境

### 8. AI 集成 (ai/)

- **MCP Server** — 标准协议服务器，6 个工具
- **系统提示词** — LLM 上下文注入
- **工具配置** — 各 AI 平台的配置文件

## 操作码编码原理

易衍的核心创新：**操作码 = 卦象爻位二进制值**

六十四卦的每一卦由六爻组成，阳爻（⚊）编码为 1，阴爻（⚋）编码为 0。从下到上依次为 bit0 到 bit5。

```
䷀ 乾 = ⚊⚊⚊⚊⚊⚊ = bit5~bit0 = 111111 = 63
䷁ 坤 = ⚋⚋⚋⚋⚋⚋ = bit5~bit0 = 000000 = 0
䷾ 既济 = ⚊⚋⚊⚋⚊⚋ = bit5~bit0 = 010101 = 21
䷿ 未济 = ⚋⚊⚋⚊⚋⚊ = bit5~bit0 = 101010 = 42
```

这种编码使得：
1. 操作码具有语义——每条指令的"卦性"直接编码在操作码中
2. 变异操作自然——翻转爻位 = 翻转操作码 bit = 变为另一条指令
3. 交叉操作直觉——两个卦象的爻位交叉 = 两条指令的基因重组

```

        │
        ▼

        │
        ▼
┌──→ 评估适应度（多平台模拟）
│       │
│       ▼
│   选择（锦标赛/轮盘赌/排名）
│       │
│       ▼
│   交叉（单点/两点/均匀）
│       │
│       ▼
│   变异（爻位翻转/修饰符变异/操作数变异）
│       │
│       ▼

│       │
│       ▼
└── 收敛检测 ──否──→ 继续进化
        │
        是
        ▼
输出最优个体
```

## 数据格式

### EVB 字节码格式

```
偏移    大小    内容
0x00    4       魔数 "EVOB"
0x04    2       版本号 (3)
0x06    2       头部长度
0x08    2       基因座数量
0x0A    N*4     基因座偏移表
--- 头部结束 ---
        ...     指令字节码
```

### EVOI 可执行映像格式

```
偏移    大小    内容
0x00    4       魔数 "EVOI"
0x04    2       版本号
0x06    2       入口基因座索引
0x08    ...     EVB 段（代码）
        ...     数据段
        ...     符号表
        ...     重定位表
```
